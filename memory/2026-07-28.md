# Memory - July 28, 2026

## Reservation Confirmation Fix (Morning)

### Problem
Reservation confirmation emails stopped going out ~3 days ago (last sent July 25).
Isabel reported guests not receiving confirmations.

### Root Cause
The `/api/cron/reservations` entry was **removed from vercel.json** at some point.
Commit `9a98c958` removed it with message "Supabase edge function handles this now" — but the edge function wasn't actually working.

### Fix Applied
1. Added `/api/cron/reservations` back to vercel.json (every 15 min)
2. Committed and pushed: `4952de88`
3. Manually triggered cron to clear backlog

### Results
- **224 confirmation emails sent**
  - La Luna: 148 emails
  - Coyol: 76 emails
- No errors
- System back to normal

### Backups
Saved to `backups/coyol-website-2026-07-28/`:
- vercel.json (with cron restored)
- reservations.ts (cron endpoint)

### Lesson
Stick to ONE system (Vercel cron) — don't switch between Vercel and Supabase Edge Functions.
The cron approach with `email_sent` flag is simple and reliable.

## UPDATE: Emails NOT Actually Sending (11:57 AM)

### Real Problem Found
The 224 emails were NOT actually sent — only marked as `email_sent: true` in database.

**Root causes:**
1. `RESEND_API_KEY` was **missing** from Vercel environment variables entirely
2. The cron marked emails as sent BEFORE actually sending (swallowed errors)
3. First deploy attempt failed (exit code 127)
4. Marion added new Resend API key but it's **invalid** — test returned "API key is invalid"

### Current Status
- Vercel cron restored ✅
- vercel.json updated ✅
- RESEND_API_KEY added to Vercel env vars ✅
- But API key is invalid ❌
- **No emails actually going out yet**

### Still Pending
1. Marion needs to create a NEW valid Resend API key with Full Access
2. Update the key in Vercel environment variables
3. Redeploy
4. Reset all `email_sent = false` for reservations from last 3 days
5. Trigger cron again to actually send the emails

### Code Fix Needed
The cron should mark `email_sent = true` AFTER successful send, not before.
Currently it marks sent, then tries to send, swallowing any Resend errors.
