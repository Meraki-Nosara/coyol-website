### Capacity Control (NEW)
Added seating capacity settings to prevent overbooking:

**Admin Settings URLs:**
- La Luna: https://coyolnosara.com/laluna/admin/settings
- Coyol: https://coyolnosara.com/restaurant/admin/settings

**How it works:**
1. Staff sets max guests per shift (Breakfast/Lunch/Dinner1/Dinner2)
2. System counts total guests already booked in that shift
3. If party size exceeds remaining capacity → booking blocked
4. Shows clear error: "First Seating is fully booked" or "Only X seats remaining"

**Default capacities:**
- Breakfast: 40 guests
- Lunch: 50 guests
- Dinner 1: 50 guests
- Dinner 2: 50 guests

- Prevents Vercel edge cache from serving stale content
- Fixed race condition on mobile where slots would flash then disappear

## Due Diligence Portal (NEW - Oct 28 PM)

### Project Overview
Marion requested a buyer-focused due diligence portal for the Espavel-Niki transaction. Purpose: give Niki, Zack, and their legal team a clear, organized view of the transaction documents.

**URL:** https://coyolnosara.com/portal/dd/espavel-niki

### Architecture
- Built on existing client portal pattern (uses Supabase + access codes)
- Reuses private bucket pattern from Legal Mar Azul system
- Access code authentication per user role

### Structure (9 Sections)
1. **Transaction Overview** — Property summaries, purchase structure, payment schedules
2. **Property Titles** — Registry certifications, surveys, ownership, encumbrances
3. **Condominium Legal** — Registration, bylaws, plans, assembly decisions
4. **Water & Electricity** — Permits, infrastructure, availability
5. **Construction Rights** — Zoning, setbacks, building restrictions, permits
6. **Casa Espavel Construction** — Plans, specifications, contract, schedule
7. **Financial & HOA** — Fees, assessments, statements, clearance certificates
8. **Legal Disclosures** — Material litigation, restrictions, pending proceedings
9. **Legal Q&A** — Questions, responses, review progress

### Database Schema
Created SQL schema file: `coyol-website/supabase/dd-portal-schema.sql`

**Tables:**
- `dd_portals` — One per deal (access codes, verification status, deal info)
- `dd_documents` — Documents per section with verification status
- `dd_questions` — Q&A between buyers and Coyol/legal team

**Access Codes (planned):**
- `NIKI2026` — Buyer access (Niki & Zack)
- `NIKI2026A` — Buyer legal team
- `DDADMIN26` — Coyol admin
- `DDLEGAL26` — Alessia (Coyol legal)

### Verification Categories
- Property ownership
- Condominium documentation
- Water & electricity
- Construction rights
- Financial obligations
- Purchase agreements (drafting)
- Construction agreement (drafting)

### Features Built
- ✅ Access code authentication
- ✅ 9-section document structure
- ✅ Verification status dashboard
- ✅ Document list per section with status badges
- ✅ Q&A system (submit questions, view responses)
- ✅ Role-based upload buttons (admin/legal only)
- ✅ Download section buttons
- ✅ Dark UI matching Coyol brand
